FHIR R4 REST API

Live read-only FHIR R4 endpoints backed by the messages in this demo. All responses are application/fhir+json. Try the requests below — they return real data from your seeded records.

CapabilityStatement (metadata) GET /fhir/

Describes supported resources, search parameters, and security requirements (SMART on FHIR).

(click Try it)
Patient Search GET /fhir/Patient/

Returns a FHIR Bundle of all patients. Supports ?identifier=MRN, ?family=JONES, ?_id=10001. 

(click a button)
Patient Read GET /fhir/Patient/{id}

Read a single patient by MRN (US Core identifier).

(click a button)
Encounter Search GET /fhir/Encounter/

All encounters with PV1 segments. Filter by ?subject=Patient/10001.

(click a button)
DiagnosticReport Search GET /fhir/DiagnosticReport/

Lab results from ORU R01 messages. Filter by ?subject=Patient/10001.

(click a button)
Production difference: These endpoints use session auth for the demo. In a production SMART on FHIR deployment, each request would carry an OAuth2 Bearer token scoped to specific resources (e.g. patient/Patient.read). See the SMART on FHIR page for the full auth flow. The CapabilityStatement advertises these scopes.
