Da Vinci Prior Authorization

CMS-0057-F (effective 2026) requires payers to support FHIR-based prior authorization via three Da Vinci Implementation Guides. This page demonstrates the full workflow with live API calls.

Step 1 — CRD: Does this service need prior auth? POST /api/prior-auth/crd/

The EHR fires a CDS Hooks order-select hook to the payer CRD service when the provider selects an order. The payer responds with cards indicating authorization requirements. 

(click Check)
Step 2 — DTR: Documentation Templates and Rules

When CRD indicates prior auth is required, the payer provides a FHIR Questionnaire that auto-populates from the patient's EHR data using CQL (Clinical Quality Language) expressions. The provider reviews, completes gaps, then proceeds to submit via PAS.

DTR eliminates fax-based prior auth by replacing static PDF forms with smart FHIR questionnaires that pre-fill from structured EHR data. 

{
  "resourceType": "Questionnaire",
  "id": "knee-replacement-pa",
  "title": "Total Knee Replacement Prior Auth",
  "item": [
    {
      "linkId": "1",

Step 3 — PAS: Submit Prior Authorization POST /api/prior-auth/pas/

After DTR forms are completed, the provider submits a FHIR Bundle (Claim resource + supporting docs). The payer responds synchronously with approved / pended / denied. 

(click Submit Prior Auth)
Why this matters (2026): CMS-0057-F requires payers to process prior auth requests within 72 hours for urgent and 7 days for standard requests, and to provide real-time responses where possible. FHIR-based CRD/PAS/DTR replaces phone calls and faxes — reducing the average prior auth cycle from 3–5 days to minutes. Integration engineers build and maintain these payer/provider integrations.
