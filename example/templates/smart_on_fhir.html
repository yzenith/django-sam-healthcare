EHR Launch

EHR opens the app in an iframe with a launch token. App exchanges it for patient/encounter context. Used for apps embedded in the EHR workflow (e.g. CDS in Epic).

?iss=https://ehr.example.com/fhir&launch=xyz
Standalone Launch

App initiates auth independently, asks user to select patient. Used for patient portals, mobile apps, and payer-side tools that aren't embedded in a specific EHR.

?client_id=…&scope=launch+patient/*.read
Backend Services

System-to-system, no user interaction. App authenticates with a signed JWT (private_key_jwt). Used for CMS payer-to-payer exchange, bulk FHIR exports, and analytics pipelines.

grant_type=client_credentials
This demo: Uses Django session auth as a stand-in for SMART bearer tokens. The /.well-known/smart-configuration endpoint above is real and returns the correct structure. In a production deployment you would point authorization_endpoint and token_endpoint at your OAuth2 provider (Keycloak, Azure AD B2C, AWS Cognito).
